# 読書体験の改善計画

## 目的

題名や作者への先入観を離れ、冒頭から作品に出会う。現在の静かな雰囲気を保ちながら、待ち時間、操作の迷い、保存データの扱いを改善する。

## 調査結果と今回の実装範囲

| 優先度 | 現状の問題 | 改善 | 完了条件 |
| --- | --- | --- | --- |
| 高 | フロントが `/search/batch` を呼ぶが、APIに存在しない | APIに件数を制限した一括取得を実装。旧APIの404/405には単件取得で対応 | 単件・一括取得・入力範囲・障害時のテストが通る |
| 高 | 5件の取得が終わるまで最初の作品も出ない | 最初の1件を優先し、次の作品は背景で補充 | 取得中も表示中の作品を操作できる |
| 高 | 上流HTTPにタイムアウトがない。著作権ありの作品も抽選してから捨てている | 候補を起動時に絞り、通信・待機・再試行に上限を設ける | 上流障害や候補不足で要求が無期限に滞留しない |
| 高 | 保存エラーが未処理。古いID形式では同一作品が重複し得る | URLで作品を識別し、既存の栞・本棚を読み継ぐ。書き込み失敗を通知 | 旧データ移行・不正データ・保存失敗を検証 |
| 中 | アイコンだけでは判断しづらく、文字単位の演出で読むまで待たされる | 操作に短いラベルを付け、本文を一度に表示。紙色と深緑の配色、読みやすい余白に統一 | 冒頭を最初の画面の中心に置き、題名は表示しない |
| 中 | 縦スクロールや設定操作中にも作品が進む可能性 | 縦移動と横スワイプを区別し、ダイアログ・入力欄ではショートカットを無効化 | 判定ロジックをテスト |
| 中 | 誤って送った作品・削除した作品を戻せない | 直前の選択と保存リストの操作を取り消せるようにする | 戻しても保存の重複や消失が起きない |
| 中 | 栞が増えると探しづらい。文字サイズを選べない | 栞・本棚内の題名／作者検索、3段階の文字サイズ | 空の本棚と検索0件を区別して案内 |

## 追加で確認した問題

Next.js 15.5.4は、公式の重大なRSC脆弱性の対象です。同じ15.5系の修正版へ更新し、React / React DOMとNext.jsのESLint設定も対応するパッチへ更新します。

出典：[Next.js公式告知（CVE-2025-66478）](https://nextjs.org/blog/CVE-2025-66478)。公開環境への反映はPRのマージ後に行ってください。

## 実装方針

- Next.js / React と FastAPI の既存構成を維持する。
- `/search` の4フィールドを維持し、API更新を先に適用できるようにする。
- ブラウザ内保存の `likedBooks` / `favoriteBooks` と既存の書体設定を読み継ぐ。
- 保存はこのブラウザ内に限られることを表示し、クラウド同期とは案内しない。
- 作品データや利用者データを分析サービスへ送らない。
- 本番へのマージ・デプロイはこの変更には含めず、2つのPRで差分と検証結果を提示する。

## 検証と次の課題

APIは小さなCSVと模擬HTTP応答を使い、外部サービスに依存せず契約・タイムアウト・欠損データを検証する。フロントは取得・保存・操作判定のテストと本番ビルドで確認する。

実ブラウザ、実データ全件、実際の青空文庫への通信を使った確認の実施有無は、PRの検証欄に明記する。公開後は初回表示時間と取得失敗を実環境で確認し、必要なら共有キャッシュや配信基盤を検討する。ログイン、推薦アルゴリズム、クラウド同期は今回の範囲には含めない。
